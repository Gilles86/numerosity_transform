# Running the study in the BLU lab

One participant per computer. Lab Control starts `lab.py` on every client. Each participant types their number, and the
rest runs by itself: examples, training, then auction runs 1–4. At the end, a dialog shows that session's earnings.

This follows the Econ Lab intranet guide "Usage Guides > Python Experiments" (standalone Python, copied to
`N:\expfiles`). **Not yet tested on the lab PCs.**

## Once: build the Python environment (ExpMaster PC)

1. Get the code. Either `git clone -b numeral-version https://github.com/Gilles86/numerosity_transform.git`, or download
   https://github.com/Gilles86/numerosity_transform/archive/refs/heads/numeral-version.zip and unzip it. Put it under
   `C:\Users\<shortname>\Documents\`.
2. In PowerShell, in the `experiment` folder:
   ```
   powershell -ExecutionPolicy ByPass -File lab\setup_lab_env.ps1
   ```
   This puts Python 3.10 with PsychoPy and exptools2 into `experiment\lab_python` (a few minutes). It prints the paths
   you need for Lab Control.
3. Test on the ExpMaster: `& <printed python.exe> lab.py`. Use participant number `1`, and press `q` to quit a phase.
4. Copy the `numerosity_transform` folder to `N:\expfiles\<shortname>\`. The first copy takes about 15 minutes. After
   that, mirroring to the clients takes about 1 minute.

## Once: set up the study

- **`lab\lab_config.yml`**: set `results_dir` to your writable network folder, `N:\client_write\<shortname>\numerosity_transform`.
  The clients copy their results there after every phase. `lab.py` also reads it to find out which session a
  participant is in.
- **`settings\lab.yml`**: the screen is already set (1920×1080, 54.4 cm wide). **Measure the viewing distance** and set
  `monitor.distance`.
- **`lab\participants.tsv`**: which stimulus and mapping each participant gets in each session. It is generated by
  `lab\make_participants.py`. The current version assumes one fixed version per participant for all 4 sessions, with the
  5 versions balanced over 35 participants. Change it if the design is different. Participant numbers 1–35 go on the
  seating or ID cards and stay the same across sessions.

## Lab Control

Open Settings → Create → Custom Experiment, type **Python**:
- Python executable: `C:\ExpFiles\<shortname>\numerosity_transform\experiment\lab_python\<...>\python.exe`
  (`setup_lab_env.ps1` prints the exact path)
- Script: `C:\ExpFiles\<shortname>\numerosity_transform\experiment\lab.py`
- Mirror from: your `N:\expfiles\<shortname>` folder

Then select the clients, choose this experiment, tick **Mirror Experiment Files**, and click **Save and Start Clients**.

## During a session

1. Each client shows a dialog: **participant number**. The next dialog proposes the session, based on the sessions
   already completed. Check it and click OK. Unknown numbers are refused.
2. The task runs full screen. Between runs, participants see their earnings so far and continue with SPACE.
3. At the end, a dialog shows the auction bonus, the show-up fee and, in session 4, the completion bonus. The
   participant raises their hand.
4. **Payment list.** On the ExpMaster, run `<python.exe> lab\payment_list.py 1` for session 1. If everyone is paid
   after the last session instead, run `lab\payment_list.py --all`.

**After a crash or a frozen PC:** run `lab.py` again (on any PC) and type the same number. It proposes to continue with
the first phase that has no log yet. A phase that was interrupted is repeated from its start.

## Where the data is

- **On each client:** `%USERPROFILE%\numerosity_transform_logs`. This is deliberately not `C:\ExpFiles`, because
  mirroring would delete it.
- **On the network:** `results_dir`, with the same layout plus `earnings\`.
- **After each session:** copy `results_dir` to the project's `_behavioural_lab` folder on the department share. The lab
  handbook says data on the lab PCs is deleted automatically.
